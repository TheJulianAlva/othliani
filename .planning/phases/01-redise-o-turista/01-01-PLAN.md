<design_decisions>
These are the planner's resolutions of the "Claude's Discretion" items in `01-CONTEXT.md`. They are
binding on **every plan in this phase**, because nine plans execute in parallel against this API and
would otherwise each invent their own token-access mechanism.

**File and class names** (snake_case, alongside — never replacing — `app_theme.dart`):

| File | Public API | Role |
|---|---|---|
| `frontend/lib/core/theme/turista_colors.dart` | `class TuristaColors` — `static const Color` fields | Raw D-03 palette values. Turista-specific. The ONLY file allowed to hold raw ARGB literals. |
| `frontend/lib/core/theme/veltur_tokens.dart` | `class VelturTokens extends ThemeExtension<VelturTokens>` | App-neutral token *contract* (semantic colors + radii + shadows). Holds no Turista values. Phase 2 constructs its own instance. |
| `frontend/lib/core/theme/turista_theme.dart` | `class TuristaTheme` — `static ThemeData get lightTheme`, `static const VelturTokens tokens` | Binds Turista values into the neutral contract and assembles `ThemeData`. |

**Why an app-neutral extension rather than Turista-named tokens:** D-02 requires the shared widgets in
`core/widgets/` to be reusable by Guía "sin duplicar widgets". A widget that reads
`VelturTokens.of(context)` works unchanged under any theme that registers a `VelturTokens` instance;
a widget that imports `TuristaColors` directly does not. The Turista-specific *values* still live in
a Turista-specific file, satisfying D-01.

**The single token-access idiom every plan uses:** `VelturTokens.of(context)` for semantic colors,
radii and shadows; `Theme.of(context).colorScheme` for primary/surface/error; and
`Theme.of(context).textTheme` for type. No plan imports `TuristaColors` outside
`turista_theme.dart`.

**`VelturTokens.of` is non-null.** It returns the registered extension, or a documented
`VelturTokens.fallback` const when none is registered. Rationale: a missing registration must degrade
to a warm-but-plain rendering during a live pitch recording, never to a null-check crash. The tests in
Task 2 assert the real theme *does* register it, so the fallback is a safety net, not the live path.

**Radius mapping** (the fine-grained D-05 mapping left to discretion): `radiusSm` (10) for input
fields and small chips; `radiusMd` (16) for cards, list items and modal top corners; `radiusLg` (24)
for primary buttons, elevated panels and bottom sheets; `radiusXl` (32) for hero cards; `radiusFull`
for pills, avatars and circular controls.
</design_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pub.dev → build | A new third-party package (`google_fonts`) enters the dependency graph. |
| device → fonts.gstatic.com | New outbound HTTP egress at app runtime to fetch the Poppins font files. |
