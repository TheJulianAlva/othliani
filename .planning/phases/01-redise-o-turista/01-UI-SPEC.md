## Spacing Scale

Declared values (multiples of 4 — matches the existing `AppSpacing` class in
`frontend/lib/core/theme/app_constants.dart`, already 8-point-compliant; no change needed):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (chip padding, small gaps) |
| md | 16px | Default element spacing (card padding, standard gaps) |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps (large button padding, screen margins) |
| 2xl | 48px | Major section breaks — not yet defined in `AppSpacing`; add if a screen needs it |
| 3xl | 64px | Page-level spacing — not yet defined in `AppSpacing`; add if a screen needs it |

Exceptions: icon-only touch targets (e.g. the walkie-talkie PTT button, swap-currency icon
button) use 56-64px regardless of the 8-point scale, to preserve a comfortable thumb target —
this matches current app conventions (`WalkieTalkieButton` is already 56px) and is not a
regression.

## Radius & Shadow Tokens

Locked by D-05 — replaces the app's current 5-12px radii and flat `Colors.black12` shadows.
These are new tokens specific to the Turista theme (not written into the shared
`app_theme.dart`/`app_constants.dart` used by Agencia — see Implementation Notes below).

| Token | Value | Usage |
|-------|-------|-------|
| radius-sm | 10px | Small chips, input fields |
| radius-md | 16px | Cards, list items, modals corners (top) |
| radius-lg | 24px | Primary buttons, elevated panels, bottom sheets |
| radius-xl | 32px | Large hero cards (e.g. walkie-talkie channel card) |
| radius-full | 9999px | Pills, circular buttons (PTT button, avatar, FAB) |

| Shadow | Value | Usage |
|--------|-------|-------|
| shadow-sm | `0 2px 8px rgba(43,29,20,0.06)` | Cards, chips, resting elements |
| shadow-md | `0 8px 24px rgba(43,29,20,0.10)` | Raised buttons, active cards |
| shadow-lg | `0 16px 40px rgba(43,29,20,0.16)` | Modals, phone-level containers, floating action elements |
| shadow-glow-primary | `0 0 0 8px rgba(232,98,61,0.14)` | Active/recording state ring around primary controls (e.g. PTT button while recording) |
| shadow-glow-danger | `0 0 0 10px rgba(229,72,77,0.16)` | Alert/live-transmission state ring |

All shadows use a warm brown tint (`rgba(43,29,20,...)`), never `Colors.black12`/generic gray —
this is the visual signature that separates the redesign from the old flat Material look.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Regular (400) | 1.5 |
| Label | 14px | Semibold (600) | 1.4 |
| Heading | 20px | Semibold (600) | 1.2 |
| Display | 32px | Semibold (600) | 1.15 |

**Note on weight consolidation:** the sketches (`default.css` usage) mix weights 600/700/800
across chips, buttons, and large numeric displays. Per CONTEXT.md, "los sketches son dirección
de diseño, no plantilla literal" — this contract consolidates to exactly **2 weights**
(Regular 400 + Semibold 600) for a disciplined, executor-actionable type system. Poppins
Semibold already reads confidently warm/bold at large sizes (screen titles, the walkie-talkie
hint's `<strong>`, the currency result figure) without needing a heavier 700/800 weight.

Font sizes map to `default.css` tokens as follows: Body = `--text-base` (16px), Label =
`--text-sm` (14px), Heading = `--text-xl` (20px, used for `topbar h2`), Display = a rounded 32px
(between `--text-3xl`/30px and `--text-4xl`/36px, matching the existing `fontSize: 32` already
used for the currency conversion result in `currency_converter_screen.dart:388`).

| Dominant (60%) | `#fff8f0` | Screen/page background (`scaffoldBackgroundColor`) |
| Secondary (30%) | `#ffffff` (surface) / `#fff2e6` (surface-warm variant) | Cards, bottom nav bar, modals, list items, chips |
| Accent (10%) | `#e8623d` (terracota, hover `#d1502e`, soft `#fce3da`) | Reserved for: primary CTA buttons (elevated buttons, "Convertir"/"Enviar" actions), the walkie-talkie PTT button, active/selected bottom-nav item, focused input border, primary text links/icons |

decorative backgrounds — only the elements listed above.

## Copywriting Contract

This phase is a **visual/UX redesign only** (per phase boundary in `01-CONTEXT.md`) — no new
user flows or copy are invented. Existing functional copy is preserved; only its typography,
color, and container styling change. New copy is added only where a sketch explicitly
introduces an interaction affordance (the walkie-talkie hold-to-talk label) that the current
app lacks as a visible label.

| Element | Copy |
|---------|------|
| Primary CTA (walkie-talkie hold-to-talk) | "Mantén presionado para hablar" — new visible label/semantics hint for `WalkieTalkieButton`, per canonical sketch `002-turista-walkie-talkie` winning variant B. Existing socket/recording logic is unchanged. |
| Empty state — Itinerario | Existing copy "No hay eventos planificados." (`itinerary_screen.dart:44`), preserved verbatim, restyled with a warm icon + `EmptyStateWidget`-style layout instead of a bare centered `Text`. |
| Empty state — Chat | Existing l10n string `typeMessage` = "Escribe un mensaje..." (`chat_screen.dart:41`), preserved verbatim, restyled with warm typography/icon instead of a bare centered `Text`. |
| Error state — Itinerario load failure | Existing dynamic `state.message` (bloc-provided, `itinerary_screen.dart:40`) rendered inside a danger-token banner (background `#fbe0e1`, text `#e5484d`/`#2b1d14`) instead of bare `Text`. No new copy invented — the message content stays whatever the bloc/failure mapping already produces. |
| Error state — Currency converter | Existing l10n strings `invalidAmount` = "Cantidad inválida" and `noNumberFound` = "No se encontró número" (`currency_converter_screen.dart`), shown via `SnackBar` restyled with danger tokens. |
| Error state — Walkie-talkie channel denied | Existing `SnackBar` text "El canal está ocupado..." (`walkie_talkie_button.dart:60-66`), restyled with warn/danger tokens. Optional refinement (Claude's discretion, not required): align wording closer to the canonical sketch's "🔒 El canal está ocupado, espera tu turno…" if it reads more naturally in context. |
| Destructive confirmation | No new destructive actions are introduced in this phase. Any existing destructive confirmations (e.g. logout) keep their current copy — only their dialog chrome (radius, shadow, button colors) is restyled to the new tokens (danger `#e5484d` for the confirm button, never terracota accent). |

## Implementation Notes (Architecture)

These are structural decisions from `01-CONTEXT.md` that the executor must follow when wiring
the tokens above into code — not visual tokens themselves, but where they live:

- **D-01 — New theme file, not an in-place edit.** Do NOT modify `frontend/lib/core/theme/app_theme.dart` or `app_colors.dart` in place — those stay serving Agencia's current navy look. Create a Turista-specific theme (e.g. `frontend/lib/core/theme/turista_theme.dart`, following the existing `snake_case` file convention) that assembles the tokens above into a `ThemeData`, consumed only from `frontend/lib/main_turista.dart`.
- **D-02 — Generalize shared widgets, don't duplicate them.** `frontend/lib/core/widgets/` (`empty_state_widget.dart`, `info_modal.dart`, `phone_number_field.dart`, `saving_overlay.dart`) must be updated to read colors/radii from `Theme.of(context)` / theme extension tokens instead of hardcoded values (e.g. `SavingOverlay`'s `Color(0xFF1565C0)` spinner, `InfoModal`'s `Colors.white`/hardcoded 16px radius, `EmptyStateWidget`'s `Colors.grey` icon) — so Phase 2 (Guía) can reuse them unchanged with its own theme instance.
- **D-05 exact placement:** since the shared `AppBorderRadius`/`AppSpacing` classes in `app_constants.dart` are consumed by all three apps, the new radius scale (sm=10/md=16/lg=24/xl=32/full=9999) should live alongside the new Turista theme (not overwrite `AppBorderRadius`, which Agencia still depends on) — exact class/file naming is Claude's discretion per CONTEXT.md.
- **D-06 — Dark mode out of scope.** `frontend/lib/core/theme/dark_theme.dart` is not touched in this phase.
- **google_fonts dependency (D-04):** add `google_fonts` to `pubspec.yaml`; apply via `GoogleFonts.poppinsTextTheme()` (or equivalent) with Nunito as the documented fallback intent — no font asset files are bundled.
